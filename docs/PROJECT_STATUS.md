# LN-auto 项目状态与路线图

更新时间：2026-09-26

## 项目目标

LN-auto 是一个基于 MaaFramework 的 Windows 桌面自动化工具。最终目标是让用户通过桌面 GUI 创建和运行自定义工作流，包括：

- 模板识别与结果复用
- 鼠标移动、单击、双击和不同鼠标按键
- 单键、组合键与文本输入
- 等待、重试、结果验证和安全停止
- 工作流保存、加载、调试与发布

项目以“输入发送成功不等于目标应用已经处理输入”为安全原则。正式流程应通过模板、截图变化或其他可观测状态验证操作结果。

## 2026-09-26 更新内容

- 安装目录新增 `workflow/` 文件夹（与 `_internal/` 同级，卸载时保留）：`paths.workflow_dir()` 在打包模式下解析为可执行文件旁目录、源码模式下为仓库根 `workflow/`，首次启动自动创建；Inno 安装脚本通过 `[Dirs]` 创建。GUI 打开/保存工作流对话框默认指向该目录；CLI `--workflow` 相对路径优先在 `workflow/` 中查找，找不到时回退项目根。
- 工作流步骤面板右上角移除“未命名工作流”文案，改为「自动延迟」下拉：无自动延迟（默认）/固定延迟/随机延迟，选择固定或随机时弹窗设置毫秒值或范围，随工作流 JSON 的 `settings.auto_delay` 持久化。步骤列表不插入额外延迟步骤；引擎在每两个步骤之间按设置延迟，并发出 `auto_delay` 事件写入运行日志。
- 随机延迟统一改用 `random.SystemRandom`（操作系统熵源，不可被种子预测）：新增引擎 `_AUTO_DELAY_RANDOM`，同时替换 wait 步骤原先的 `random.randint` 全局伪随机。
- 主窗口状态栏右下角常驻显示鼠标屏幕坐标（`QTimer` 每 100 ms 刷新 `QCursor.pos()`），方便填写点击/移动步骤的坐标。
- 「添加到工作流」按钮更名「插入到工作流」：新动作不再总是追加到末尾，而是插入到当前选中步骤的下方（无选中时仍追加到末尾；双击动作组件行为相同），`WorkflowDocument` 新增 `insert_step(step_type, position)`。
- 运行期报错全面汉化并附用户可执行的解决建议：`win32_input.py` 的 `DirectInputError`（权限不足时提示「以管理员身份运行 LN-auto」、前台切换失败、坐标越界提示参考右下角实时坐标等）、`workflow/actions.py`（模板未找到附候选得分与降阈值建议、识别变量缺失、Maa 操作失败等）、`workflow/engine.py`（步骤失败、步骤超时附调大 `default_timeout_ms` 建议）及 v1 链路 `template_action.py`/`automation/workflow.py`。配置文件校验类报错（loader）仍为英文，未在本次范围。

## 当前架构

```text
src/window_auto/
├── application/   CLI 与 GUI 共用的应用服务
├── automation/    第一版模板动作与顺序工作流
├── config/        主配置加载与校验
├── diagnostics/   截图、模板匹配、输入与调试报告
├── gui/           PySide6 桌面工作流编辑器
├── runtime/       MaaFramework 控制器、资源和任务生命周期
├── windowing/     Windows 窗口发现与确定性选择
├── workflow/      工作流 v2 模型、执行器、事件与取消机制
└── cli.py         命令行入口
```

主要边界：

- `application/` 不依赖终端交互，供 CLI 和 GUI 共同调用。
- `workflow/` 负责数据模型、动作执行、结构化事件和协作式取消。
- `gui/` 只负责编辑、展示、确认和线程调度，不直接实现 Maa 动作。
- `runtime/` 统一管理 Maa 控制器连接、分辨率校验、资源加载和释放。

## 输入兼容性实测

本轮同时使用普通 Windows 测试窗口和实际目标窗口验证。

| 输入路径 | 实测结果 | 使用建议 |
|---|---|---|
| 非管理员 `PostMessage` | Windows 返回错误码 5（拒绝访问） | 自动化程序权限不得低于目标程序 |
| 管理员 `PostMessage` | 消息派发成功，但目标程序没有处理点击 | 不得仅凭 Job 成功判定 |
| Maa `Seize` 鼠标 | 多显示器或特殊窗口布局下出现二次坐标映射，并可能改变窗口状态 | 不作为坐标敏感场景的默认方案 |
| `foreground-precise` | 模板中心换算为客户区坐标后成功点击目标控件 | 适合需要精确前台坐标的场景 |
| `Seize + post_input_text` | 字符失真且保存时序不可靠 | 仅保留为可选兼容模式 |
| `Seize + click_key` 离散按键 | 单键和 `Ctrl+S` 等组合键成功 | 适合离散按键操作 |
| `Seize + key_down/key_up` 逐键文本 | 完整 33 字符与磁盘内容逐字符一致 | ASCII 文本的当前可靠方案 |

当前输入策略：

- `foreground-precise`：把识别点换算为客户区原始坐标，再经 `ClientToScreen` 定位真实屏幕像素；恢复并置顶目标窗口、校验最终鼠标位置后点击，适合坐标敏感的前台窗口。
- `background-window-message`：使用 `PostMessage` 并开启鼠标锁定跟随，仅适合已实测接受后台消息的目标程序。
- `foreground-compatible`：鼠标和键盘使用 `Seize`，仅适合目标窗口已经位于前台的场景。
- `background-message`：使用 `PostMessage`，只适合目标应用实测确认支持的场景。
- `driver-interception`：预留 Interception 驱动级输入，需要用户显式安装驱动和管理员权限。

逐键文本目前按 US 键盘虚拟键映射支持 ASCII。中文等 Unicode 文本需要后续增加剪贴板粘贴或输入法专用策略，并进行目标应用验证。

## 当前限制

- GUI 创建模板目前依赖已有截图，尚未直接从选定目标窗口获取截图。
- 窗口范围默认仍按 expected 分辨率严格校验；需要整张桌面识别时要显式设置 `controller.capture_scope: "desktop"`，且桌面范围模板需按桌面识别图单独制作。
- 尚无暂停/恢复；当前只有运行、协作式停止。
- 停止只能在安全边界生效，不能中断 MaaFramework 内部正在等待的单个 Job。
- 尚无条件分支、循环、子工作流和跨步骤通用表达式。
- 工作流报告尚未统一覆盖 v2 的全部事件和输入验证结果。
- 模板识别后可点击匹配中心，但 GUI 尚未提供模板预览和单步识别调试。
- GUI 当前以步骤列表为主，不是自由连线流程图。

## 后续阶段计划

### M4：截图、模板与单步调试

目标：让非开发用户可以在 GUI 内完成模板制作和步骤验证。

- 在 GUI 中连接选定窗口并获取截图。
- 自动探测原始分辨率、截图分辨率和 DPI 缩放。
- 从当前目标窗口直接获取截图，并提供可缩放预览。
- 已有矩形框选结果统一保存到 `assets/resource/image/` 本地模板目录。
- 在属性编辑器中预览模板、阈值和匹配框。
- 支持“测试当前步骤”和“从当前步骤运行”。
- 展示匹配分数、匹配区域、操作前后截图和差异图。
- 失败时给出可执行的恢复建议，而不是只显示异常文本。

验收标准：

- 用户无需手工编辑 JSON 即可制作模板并完成一次识别。
- 测试步骤不会误执行后续步骤。
- 分辨率不匹配在发送输入前给出明确校准流程。

### M5：工作流控制能力

目标：从线性动作列表升级为可表达常见自动化逻辑的执行器。

- 暂停与恢复。
- 等待模板出现、等待模板消失。
- 条件分支。
- 有上限的循环与超时保护。
- 用户变量和步骤输出引用。
- 子工作流。
- 统一重试、退避和失败处理策略。
- 静态检查不可达步骤、缺失变量和危险无限循环。

验收标准：

- 执行器可表达“识别状态 → 选择分支 → 重试 → 结束”的常见自动化流程。
- 任意循环都有次数或时间上限。
- 停止请求不会导致重复输入。

### M6：验证、诊断与目标程序兼容性

目标：让每次输入都能选择适合的验证方式，并形成可审计报告。

- 为输入步骤增加后置验证规则。
- 支持画面变化、模板出现/消失和区域变化验证。
- 增加输入兼容性探针，区分“已派发”和“目标已处理”。
- 检测目标窗口焦点、关闭、最小化、权限等级和分辨率变化。
- 增加 Unicode 文本策略并恢复用户剪贴板。
- 评估管理员权限和 Interception 驱动方案，但不自动安装驱动。
- 生成统一运行报告、时间线、截图证据和脱敏日志。

验收标准：

- GUI 不再把 Maa Job 成功直接显示为业务操作成功。
- 失败报告能够回答失败步骤、使用的输入方式、验证证据和恢复方式。

### M7：发布与维护

目标：交付可安装、可升级的 Windows 桌面应用。

- 增加 CI 测试、静态检查和打包验证。
